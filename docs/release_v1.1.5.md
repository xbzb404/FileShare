# FileShare v1.1.5

共享账户的作用范围这回被钉死了：**禁止一切系统登录、只对当前共享目录有权限、
目录一换旧授权自动收回**。以前只有「只授给这个账户」，现在是「只授给这个账户，
而且过期就收」——两者差着一个能长期留着的后门。

## 下载

**FileShare.exe**（22.7 MB，单文件免安装、无外部依赖，Windows 10/11 x64）

## 一、禁止系统登录

账户除了走 SMB，登不进桌面、开不了远程、也跑不了后台任务：

| 拒绝的用户权利 | 效果 |
| --- | --- |
| `SeDenyInteractiveLogonRight` | 本机控制台登不进去 |
| `SeDenyRemoteInteractiveLogonRight` | 远程桌面进不去 |
| `SeDenyBatchLogonRight`（**本版新增**） | 不能被挂成计划任务在后台跑 |
| `SeDenyServiceLogonRight` | 不能以服务身份运行 |

同时：密码不能改、永不过期，并按 SID 从管理员组 / 备份操作员组 / 远程桌面用户组 /
远程管理用户组（WinRM）里移除。用的是 LSA 的 `LsaAddAccountRights` 逐条追加，
不整块导入安全模板，不会顺手改掉本机其它账户的用户权利配置。

「从网络访问」这一条**必须保留**，否则 SMB 直接失效——这是本方案的天花板。

## 二、权限仅限共享目录

- 目录上只写一条属于该账户的显式 ACE：只读 `(OI)(CI)(RX)`、可写 `(OI)(CI)(M)`
- 网络侧它只能看到共享目录，没有路径就没有入口；本机侧被上一条挡住
- 体检新增提醒：**「该账户还能访问本机另外 N 个共享」**。那些是用户自己建的共享，
  共享权限默认就是 `Everyone` 读，程序不去动（动了可能断掉别人正在用的东西），
  只把清单摆出来让人自己决定

> 仍有必要知道的：登录后的账户天然属于 `Authenticated Users`，所以对
> `Authenticated Users` 开放的其它目录它照样能读。要彻底隔离敏感目录，
> 仍建议加一条拒绝项（Deny 优先于 Allow）：
> `icacls "<敏感目录>" /deny FileShare:(OI)(CI)(RX)`。

## 三、目录切换时权限跟着更新

这是本版的核心修复。以前只「加权限」，目录换过之后旧目录上的 ACE 还留着：

- **多删**：目录被移出共享、共享换了目录、或者共享账户改了名 → 旧目录上的显式 ACE 逐条撤销，
  记录文件里的对应条目一起删掉（重启后不会又漏一次）
- **少补**：当前共享目录缺授权就补上
- **级别纠正**：只读↔可写切换时先 `/remove:g` 再加——`icacls /grant` 只会叠加，
  从可写「降」成只读时直接加 `(RX)` 是没有任何效果的
- **幂等**：已经是对的样子就一个字节都不改，不会因为反复同步把正在读文件的客户端卡住

点「修复局域网访问」和开启共享都会走这套逻辑，所以清理旧授权不需要单独操作。

## 升级后要做的

1. 服务设置 → Windows 共享 → **修复局域网访问**（跑一次即可，幂等）
2. 如果体检里出现「该账户还能访问本机另外 N 个共享」，按需在
   「计算机管理 → 共享文件夹」里收紧或停用
3. 之前共享过、后来删掉的目录，这次会被自动收回授权，无需手动清理

## 已知边界

- **组换不来免密**：`Guest` 进不了「从网络访问这台计算机」（错误 1385），
  这是用户权利层面的限制，与组、与目录权限都无关
- 管理员主动把它加进 Administrators 或改本地安全策略，这套限制会失效；
  每次修复会重新踢组、重写拒绝权利，但挡不住有管理员权限的人主动拆
- 不需要任何认证的只读共享，仍然只有 HTTP / FTP 两条路
