# FileShare v1.1.4

SMB 去掉「免密（Everyone）」模式，只保留指定账户；账户自动加固成「只能网络登录」。
同时把 FTP 的匿名只读开关放到界面上——那是 Windows 上真正能「不输密码」的只读通道。

## 下载

**FileShare.exe**（22.8 MB，单文件免安装、无外部依赖，Windows 10/11 x64）

## 为什么删掉免密模式

免密要靠 `Guest` 登录，而 Win10/11 默认把 `Guest` 放进「拒绝从网络访问这台计算机」：
匿名连接在登录阶段就被拒（实测错误 1385），客户端只会一遍遍弹「输入网络凭据」。
继续保留这个开关，等于让用户以为能开、实际永远连不上。

## SMB 的变化

- **只支持指定账户**：共享权限和目录权限都只授给面板上那个账户，不再给 `Everyone`
- **自动迁移**：旧配置里的 `mode` 键会被丢弃；开共享时会把以前加在目录上的
  显式 `Everyone` 授权逐条收回（继承来的不动）
- **账户加固**（新增，修复时自动做）：
  - 拒绝本地登录、远程桌面、作为服务登录，**只保留从网络访问**
  - 用户不能改密码（改了所有客户端一起断）、密码永不过期
  - 按 SID 从管理员组 / 远程桌面用户组 / 备份操作员组里移除（组名本地化也不影响）
  - 用的是 LSA 的 `LsaAddAccountRights`，只动这个账户，不会覆盖别人的用户权利配置
- 面板会显示加固状态：已加固 → 绿字说明；未加固 → 提示点「修复局域网访问」

> 仍需注意：任何账户登录后天然属于 `Authenticated Users`，所以本机其它对
> `Authenticated Users` 开放的共享它也能读。要彻底隔离，给敏感目录加一条拒绝项：
> `icacls "<敏感目录>" /deny FileShare:(OI)(CI)(RX)`（Deny 优先于 Allow）。

## FTP 的匿名只读（新的界面开关）

FTP 不涉及系统账户，天生支持匿名：

- 服务设置 → FTP → **允许匿名访问**：用户名填 `anonymous`，或者随便填（`admin` / `123` 都行）
- 匿名会话**固定只读**：即使「允许上传」开着也不会写盘（服务端构造时就强制关掉写权限）
- 适合电视盒子、播放器、临时访客

所以「局域网只读、不输密码」的正确姿势是 HTTP 或 FTP，而不是 SMB。

## 质量

- **116 项自动化测试全绿**，本版新增 12 项：
  - 共享权限必须授给指定账户（不能出现 `/grant:Everyone`）
  - 老共享授 Everyone 时必须重建收紧
  - 迁移：旧 `mode` 键被丢弃、旧的 Everyone 目录授权被收回且不动账户授权
  - 加固命令序列（`/passwordchg:no`、永不过期、按 SID 踢组、写入三条拒绝权利）
  - 加固失败如实上报（不谎报成功）
  - FTP 匿名：任意凭据可登录、匿名不能上传、manager 强制只读
- 探针全过：SMB 面板 / SMB 控件 / GUI 逐页 / 滚轮 20 项 / 单实例 / 托盘 / 冒烟

## 升级说明

直接覆盖 exe。首次开启共享时会自动迁移：

1. 清掉旧配置里的免密设置
2. 收回目录上旧的 Everyone 授权
3. 建/更新 `FileShare` 账户并加固
4. 把共享与目录权限改成只授该账户

迁移只需要管理员权限，重复执行无副作用。
