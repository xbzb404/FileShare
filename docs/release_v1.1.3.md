# FileShare v1.1.3

解决「其它机器始终卡在『输入网络凭据』、怎么输都进不去」——根因是免密模式依赖的
`Guest` 账户被系统策略禁止网络登录，本版改成默认账号模式，并把可用的用户名/密码
直接摆在面板上。

## 下载

**FileShare.exe**（22.8 MB，单文件免安装、无外部依赖，Windows 10/11 x64）

## 你截图里的那个框，根因是什么

对方机器弹出「输入你的凭据以连接到 192.168.49.253」，说明 **445 端口通了、服务端也在**，
卡住的是「身份」这一环。实测这台机器：

```
net use \\192.168.49.253\IPC$ "" /user:Guest
→ 发生系统错误 1385。登录失败: 未授予用户在此计算机上的请求登录类型。
```

`Guest` 被放进「拒绝从网络访问这台计算机」（Win10/11 的默认安全策略）——这正是免密
模式失效的原因：光启用 Guest、允许空密码网络登录都没用，来宾根本拿不到网络登录权限，
客户端就只能一遍遍弹凭据框。

而同一个账户用密码走网络登录是通的：

```
net use \\192.168.49.253\IPC$ fileshare /user:FileShare
→ 命令成功完成。
```

所以正确做法不是硬去改安全策略（那等于给整机开来宾登录），而是**用账号模式**。

## 本版改动

- **默认改为「账号密码」模式**，面板直接显示「用户名 FileShare / 密码 fileshare」，
  并给一个 **复制凭据** 按钮（连地址一起复制，发给对方机器照着填）
- **检测到 Guest 被策略拦住（错误 1385）时自动切到账号模式**，并在运行日志里说明原因，
  不再让用户对着一个永远连不上的免密共享猜
- 新增**真实网络登录验证**：体检时用 `net use \\127.0.0.1\IPC$` 实际登一次
  （前后都会断开旧会话，避免错误 1219 假阴性），所以「账户存在」不再被当成「能连上」：
  - 密码不对 → 「共享账户登录验证不过：用户名或密码不正确」
  - 被策略拦 → 「被『拒绝从网络访问这台计算机』拦住」，且明确标注**程序修不了**
- 「修复局域网访问」也带这一步验证，修完当场知道成没成
- 面板提示补上关键一条：**地址必须带共享名**（`\\IP\共享名`）。只输 `\\IP` 需要先枚举
  共享，系统默认 `RestrictNullSessAccess=1` 拒绝，会一直卡在凭据框
- 免密开关文案改为「多数 Win10/11 会被策略拦住，不推荐」，被拦时给一个
  **改用账号模式（推荐）** 的按钮
- 顺手修两处：
  - 长页滚到底时，钳制逻辑用 `winfo_height()` 推算上限，比 Tk 实际可视高度少 9px，
    会把最后一行判成「越界」而回弹；改为以 Tk 自己的结论为准，并新增「能滚到内容末尾」断言
  - 第二个实例的叫门改为重试 6 次（首个实例冷启动时监听线程可能还没就绪，
    一次连不上就放弃会导致「双击没反应」）

## 你现在要做的

1. 覆盖安装新 exe，打开「服务设置 → Windows 共享」
2. 确保「免密只读」是关的（本版默认关，老配置会在开启共享时自动切换）
3. 点一次 **修复局域网访问**（管理员权限），等面板显示 ✓
4. 在对方机器上打开 `\\192.168.49.253\Fshare`，弹出的凭据框里填：
   - 用户名 `FileShare`
   - 密码 `fileshare`
   - 勾选「记住我的凭据」
