# 文件共享中心

> 把本机目录一次性共享给局域网的手机、电视、另一台电脑。
> **HTTP（浏览器直接下）/ FTP（资源管理器挂载）/ Windows 共享（SMB）三种协议同时开，一个窗口管全**，
> 还能看到谁在下载、占了多少带宽。

作者：**by zhb** · 版本 1.0.0 · 界面：tkinter + Canvas 自绘（Win11 Fluent 风格）· 单文件 exe 22.7 MB

---

## 一句话说明它能干什么

| 你想要的 | 它怎么做到 |
| --- | --- |
| 手机/电视直接看电脑里的电影 | 起 HTTP 服务，电视浏览器打开 `http://电脑IP:8080/` 点开就播 |
| 当网盘用，拖文件像本地盘 | 开 Windows 共享（SMB），资源管理器输入 `\\电脑IP\共享名` |
| 老设备只认 FTP | 内置 FTP 服务，资源管理器 / FileZilla / WinSCP 都能连 |
| 下载要快 | HTTP 支持 Range，配合本程序的多线程下载器跑满带宽 |
| 别把公司/宿舍的网上传占死 | 服务端上行、下载器各有一条限速，0 = 不限速（吃满），也可以压到 1 MB/s |
| 想知道谁在下 | 「连接监控」页按 IP 列出速度、正在下的文件、累计流量、占总带宽比例 |
| 看总带宽用掉多少 | 概览页首屏两个大数字：**共享总带宽（此刻）** 和 **近 30 秒平均**，再叠加网卡占用百分比 |
| 关掉窗口但继续共享 | 缩到系统托盘，双击图标回来 |

## 快速上手

**方式一：直接下载可执行文件**（推荐给只想用的）

到本仓库的 [Releases](../../releases) 下载 `FileShare.exe`，双击即可（单文件、免安装、无依赖）。

**方式二：从源码运行**（Python 3.10+，无第三方依赖）

```bash
git clone git@github.com:xbzb404/FileShare.git
cd FileShare
python main.py          # 直接运行
python -m unittest discover -s tests    # 跑测试（74 项）
python build_exe.py     # 自己打包成单文件 exe（需 pip install pyinstaller）
```

**用法**

1. 「共享目录」页点 **添加目录**，选一个文件夹（电影、软件、照片都行）。
2. 服务默认会自动启动；也可以在 **概览** 页的协议磁贴或 **服务设置** 页逐个启停。
3. 同一局域网的设备访问里面显示的地址：
   - 浏览器：`http://192.168.x.x:8080/`
   - 资源管理器：`ftp://192.168.x.x:2121/`（账号 `share`，密码 `fileshare`，可在设置页改）
   - Windows 共享：`\\192.168.x.x\目录名`（需要管理员权限，见下）

> **SMB 需要管理员权限**。程序默认以普通权限启动（HTTP/FTP 完全不受影响），
> 侧边栏会显示「○ 普通权限」并给一个 **以管理员重启** 按钮，点一下就好。
> 这样设计是因为强制提权会带来副作用（看不到已映射的网络驱动器等）。

## 界面

六个页面：

- **概览**：三张协议磁贴（状态灯 / 访问地址 / 连接数 / 端口，可直接启动停止）、
  **带宽仪表**（共享总带宽 / 近 30 秒平均 / 网卡占用条 / 90 秒曲线）、共享目录速览、怎么访问。
- **连接监控**：谁在下载。四个汇总量（活跃连接 / 下载设备 / 当前总带宽 / 近 30 秒平均），
  按 IP 一行一张卡（速度、连接数、累计、占总带宽百分比、正在传的文件），
  下面还有逐条连接明细（IP / 方向·协议 / 文件 / 速度 / 已传输 / 时长）。
- **共享网络**：局域网互发现。开了共享后本机监听固定探测端口（默认 47610），
  其他主机跑本软件就能被互相找到；启动时自动扫一次，停留在本页每 30 秒无感重扫，
  切回本页立即重扫，也可手动扫描；主机关闭后条目自动消失。
  每台主机一行，HTTP / SMB / FTP 入口直接点击访问——HTTP 多浏览器时询问用哪个。
- **共享目录**：添加 / 启用停用 / 打开 / 移除。
- **服务设置**：HTTP 端口与上传开关、FTP 端口与账号密码、SMB 只读开关、两条限速滑块。
- **下载**：粘贴链接即下，多线程 + 断点续传 + 断线重连。
- **运行日志**：每个请求、每次登录、每次启停都有记录，可按颜色区分。

## 三种协议各自的定位

| 协议 | 端口 | 适合 | 能力 |
| --- | --- | --- | --- |
| **HTTP** | 8080 | 浏览器、电视盒子、投屏 App、本程序的多线程下载器 | 目录浏览、Range 断点续传、多线程下载、可选网页上传（PUT，**默认关闭**） |
| **FTP** | 2121 | Windows 资源管理器、FileZilla、WinSCP、老设备 | 列目录（LIST/NLST/MLSD）、下载、上传、续传（REST）、建目录、删除、改名 |
| **SMB** | 445（系统） | Windows 资源管理器当网盘用、局域网大文件 | 系统原生实现，只读/读写可切 |

三个协议共享**同一份共享目录列表**：添加一个 `media` 目录，就同时得到
`http://IP:8080/media/`、`ftp://IP:2121/media/`、`\\IP\media` 三个入口。

## 带宽监控（只统计本软件共享的流量）

概览页首屏的两个大数字，就是「现在总共用了多少带宽」：

| 指标 | 口径 |
| --- | --- |
| **共享总带宽（此刻）** | 发送给客户端的字节 + 客户端上传进来的字节，每秒刷新 |
| **近 30 秒平均** | 最近 30 条采样按时间加权平均（不是简单算术平均，UI 卡顿/系统睡眠时更准） |
| **网卡占用** | 共享总带宽 ÷ 网卡链路速率。链路速率用 `GetAdaptersAddresses` 直接读，按 IP 精确匹配到承载服务的网卡（本机是 100 Mbps 的「以太网」） |

**只统计本软件产生的共享流量**：读的是自己的计数器，不是系统全局流量，
所以后台的浏览器、微信、系统更新都不会混进来。同时也**不含内置下载器** ——
那是本软件当客户端去下别人的东西，曲线里画成橙色并标「不计入」，
它的速度在「下载」页和状态栏单独显示。

> 单位换算这里踩过一个坑：统计出来的是**字节/秒**，网卡链路是**比特/秒**，
> 算占用率要 ×8。第一版忘了乘，4 MB/s 跑在 100 Mbps 上显示成 4.2%（实际 33.6%），
> 是带宽探针对比限速值才发现的。

## 带宽控制

「服务设置 → 带宽限制」有两条独立的滑块：

- **服务端上行**：别人从你这里下载的总速度（HTTP + FTP 共用这一份额度，不是每连接各一份）；
- **内置下载器**：本程序自己下载时的总速度。

预设按钮有 不限速 / 1 / 5 / 10 / 50 / 100 MB/s，也可以拖滑块精确到 0.5 MB/s。

**不限速（0）时会尽量吃满**：服务端一次搬 512 KB、事件循环只管 socket、
文件读放在线程池，回环实测单线程 1.2 GB/s、8 线程 2.1 GB/s —— 也就是说瓶颈在网卡，
不在程序（千兆网卡实际约 110 MB/s）。

---

## 多线程下载器

- **分片**：把文件按 N 段切开（默认 8 线程，可调到 32），每段一条连接、一个 `Range` 请求，
  各自用 `os.pwrite` 写到同一个 `.fspart` 文件的对应偏移，不需要把数据堆在内存里。
- **断点续传**：每段进度写进 `.fsmeta`（JSON）。暂停、关掉程序、甚至断电，
  下次在「下载」页点继续，会按记录的偏移接着下。
- **断线重连**：某一段断了就从该段当前位置重连（指数退避，最多 60 次），不会从头再来。
- **不限速/限速**：所有段共用一个令牌桶，所以设的是总速度。
- **不覆盖**：目标同名时自动加 `(1)(2)` 后缀。

## 为什么 HTTP/FTP 是自己写的

不是因为轮子好看，是三个实际原因：

1. **要打包成一个 exe**：少一个第三方依赖就少一份体积和启动开销，
   标准库 `asyncio` + `socket` 已经够用；
2. **限速必须是全局的**：现成的 FTP 库按连接限速，8 个连接就是 8 倍上限，
   没法实现「总共只给 10 MB/s」；这里 HTTP 和 FTP 共用一个令牌桶；
3. **要知道每个 IP 占多少带宽**：需要在自己的传输循环里埋点，第三方库里插不进去。

代价是协议细节得自己啃：`Range` 单段解析、`416` 响应、`REST` 续传偏移、
`PASV/EPSV/PORT` 三种数据通道、`NLST` 只回名字（`LIST` 回长格式）、`MLSD` 的
`type=file;size=...` 格式……这些都在 `tests/test_core.py` 里用真实客户端
（`urllib` / `ftplib`）验过，29 个用例。

## 上传与安全

**上传出厂全关**：HTTP 的网页上传和 FTP 的写命令默认都不开启，要在「服务设置」里
手动打开对应开关；关掉服务再启动不会自己变回开启（配置迁移会强制重置）。
打开开关后，上传要过 `uploadguard.py` 的全套防护：

- **路径不能跳出共享目录**：`..`、绝对路径、盘符、URL 编码绕过（`%2e%2e`）
  全部拒绝；再对父目录做 `realpath` 比对，防目录联接/符号链接指到共享外。
- **文件名消毒**：拒绝 NTFS 备用数据流（冒号）、Windows 保留设备名
  （CON/NUL/COM1…）、控制字符、尾随点与空格（`a.exe.` 会被 Windows 当 `a.exe`）。
- **可执行文件禁执行**：`.exe/.bat/.ps1/.js/.lnk…` 落盘自动改名 `xxx.noexec`，
  并追加「拒绝执行」ACL（SID `S-1-1-0`，deny 优先）—— 手工改回 `.exe` 也跑不起来。
  FTP 的 RNTO 改名同样受控：不能借改名把文件变回可执行名或造 ADS。
- **不覆盖已有文件**：HTTP 409 / FTP 553，只有 REST 断点续传例外。
- **防写满磁盘**：HTTP 上传声明大小超过剩余空间直接 507。
- 上传流量照常计入「连接监控」，限速滑块同样约束上传速度。

## 已知限制

- **SMB 需要管理员权限**，这是 Windows 的限制；没有管理员时 HTTP/FTP 一切正常。
- HTTP 上传只支持 `PUT`（网页里已经带了上传按钮，走 `fetch`），不支持表单 `POST`。
- HTTP 的 `Range` 只处理**单段**（多段请求按第一段响应），够多线程下载和续传用了。
- FTP 不支持 FTPS（不可加密），局域网内使用；要跨公网请自行套隧道。
- 目录大小统计只数一层文件（最多 400 个），递归统计会把界面拖死。
